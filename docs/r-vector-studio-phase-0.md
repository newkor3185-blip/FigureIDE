# R Vector Studio implementation notes — Phases 0–5

**Status:** Phases 0-5 and Phase 3.5 development workspace improvements implemented; Phase 1 startup/UI and Phase 3 SVG paste issues reproduced and fixed.
**Base revision:** `6e191ccf14db96bf4aaa1e0bc1950068e127219b` (2026-10-26 checkout).

## Repository findings

| Concern | Existing implementation |
|---|---|
| Desktop entry point | `apps/vectorcraft/src/main.rs` constructs `vectorcraft_ui_egui::VectorcraftApp` and hosts it through `eframe::App`. |
| UI framework | egui 0.37 / eframe 0.37; UI code is in `crates/ui-egui`. |
| Workspace layout | `crates/ui-egui/src/lib.rs` builds the main frame; `panel_docking.rs` owns the canvas and docked editor panels. |
| Document model | `vectorcraft-engine::Session` owns document state; vector objects and artboards are in `vectorcraft-doc`. |
| Editing and history | User changes flow through `VectorcraftApp::run` to engine commands; `Session` keeps per-document undo/redo history. |
| SVG | `vectorcraft-svg` parses and writes SVG; import/export are reached through engine file commands and the existing UI file services. |
| File dialogs and I/O | `Services` supplies open/save pickers and file readers/writers. `picks` handles deferred native dialogs; `io` reports read/write failures and respects automation file roots. |
| Tests | Unit and integration tests live alongside `crates/ui-egui`, `crates/engine`, `crates/svg`, and other workspace crates. `cargo xtask ci` is the repository-wide gate. |
| Build prerequisites | Rust toolchain 1.95+ and the native platform dependencies documented in `docs/development.md`. R is an optional external runtime and is not a Cargo dependency. |

## Phase 1 implementation

1. The editor lives in the existing egui UI crate and shares the current app frame.
2. The desktop opens with one R script editor and console on the left and the existing docked VectorCraft workspace on the right. Both dividers can be resized.
3. R scripts open/save through VectorCraft's file picker and file services. Ctrl/Cmd+S saves; Ctrl/Cmd+Shift+S saves as; Ctrl/Cmd+Enter runs the selected code or caret line; Ctrl/Cmd+Shift+Enter runs the script.
4. R detection runs off the UI thread and checks `R_HOME`, `PATH`, and standard Windows install folders. It reports the version/path or a lookup error.
5. Phase 1 initially used a fresh `Rscript` process per request; Phase 2 replaces that bridge with the persistent session described below.

## Phase 2 implementation

1. `crates/ui-egui/src/r_session.rs` owns one long-lived `Rscript` process per workspace. Requests and responses use per-session temporary files with atomic rename and hex-encoded UTF-8 payloads, avoiding command-shell interpolation and Windows stdin behavior.
2. Console expressions, selected/current-line execution, and full-script execution use the same R global environment. Visible values, captured output, warnings/messages, and errors are returned to the console.
3. The toolbar provides Restart R and Stop R. The session also starts on the first execution; closing or stopping the workspace sends a clean stop request, then kills the process if it does not exit promptly.
4. Console history supports Up/Down and is capped at 500 distinct consecutive commands. Execution and session controls remain on worker threads.

## Phase 3 implementation

1. Every successful or failed R evaluation refreshes the named-object registry by checking actual object classes in the shared `.GlobalEnv`. Objects inheriting `ggplot` appear with their variable name and class list; temporary objects are not inserted automatically.
2. The Plot Registry lists discovered plots and offers Add to Artboard for each one.
3. Selecting Add retrieves the named object from the same `.GlobalEnv`, verifies it is a ggplot, renders it through R's SVG graphics device, reads the SVG with a 16 MiB bound, and imports it through VectorCraft's existing `clipboard.importSvg` command. It pastes the imported internal clipboard through the UI's internal-clipboard path, then groups the artwork. The result is native editable vector content, not a raster capture.
4. An unlinked Add creates a persistent labeled panel; repeating Add for an already-linked variable refreshes that panel instead of duplicating it. The R variable and panel ID remain separate from visual content. Render/import failure reports a diagnostic and keeps existing artwork unchanged. Registry data refreshes after evaluation and rendering.
5. A Windows-specific interaction bug was found in the app command wrapper: ordinary paste first adopts the system clipboard, which could overwrite the just-imported SVG with unrelated external text. The plot workflow now pastes the internal SVG without adopting external clipboard contents; ordinary paste behavior is unchanged.

## Phases 4–5 implementation

1. A linked figure panel is a named native group containing a generated-plot subgroup and an editable panel-label text object. The panel group name stores a compact `RVS_PANEL` marker with its label and R variable name; the child plot group has a separate marker. The R variable and persistent panel ID remain metadata, separate from the visual plot contents.
2. Linked panels are reconstructed from these document markers when the active document changes or reopens. Removing a panel from the document removes its live workspace association. Adding an already-linked variable refreshes its existing panel instead of creating a duplicate.
3. New panels are placed in a two-column figure grid. Labels A–D identify the initial four panels. The entire panel group can be selected, moved, and resized independently, including its label.
4. **Update Selected Panel** refreshes the selected linked panel; **Update All Panels** refreshes all links in sequence. Running the full shared script refreshes every linked panel only after the script succeeds. Successful script runs that report an error do not replace existing artwork.
5. Refresh renders the current R object to SVG, imports it using VectorCraft's SVG importer, groups the imported native objects, then calls `object.replaceGroupContents`. This command replaces only the generated subgroup's children while retaining the panel ID, generated subgroup ID, transform, label, layer position, and unrelated annotations. Each refresh is one undoable engine edit. A render/import failure leaves the prior valid plot untouched and reports the error.
6. Create/link policy: adding an unlinked variable creates one panel; adding a variable that already has a panel updates that panel in place; repeated Update All never creates panels. Panels persist with the native document through named group markers, while code and the live R session remain workspace state.

## Phase 3.5 development workspace

1. Ctrl/Cmd+Enter asks the persistent R process to parse the full editor buffer with `parse(..., keep.source=TRUE)`, selects the complete expression at or after the caret, runs it, echoes it in the console, refreshes Environment and Plot Registry, and moves the caret to the following line. A nonempty selection is still run as selected. Script execution remains Ctrl/Cmd+Shift+Enter.
2. The console accepts multiline input (Shift+Enter inserts another line), Enter/Run submits it, Up/Down recall history, and Clear console clears output. Commands show queued, running, completed, or failure status. Execution and environment/data requests stay on worker threads. The bridge captures visible output, warnings/messages, R errors, and per-session stderr diagnostics; stopping or restarting R clears stale Environment and Viewer data.
3. Global Environment reads bounded structured metadata from `.GlobalEnv`: variable name, classes, `typeof`, dimensions, length, and a short scalar preview. It offers name filtering, category labels, refresh, plot Add/Select actions, and confirmed object removal/environment clearing. It uses the same R process and does not serialize whole objects for the list.
4. Data Viewer pages data.frame/tibble rows in batches of 50, displays column names/types, supports scrolling, and truncates each displayed cell. Sorting and text filtering apply to the currently loaded page.
5. Plot Registry remains separate from Global Environment. Environment ggplots offer a route to Plot Registry. The utility area is now a seven-tab panel below the editor, and both workspace splitters keep their ratios in UI preferences.

## Current implementation boundaries

The full R script is not yet persisted in the project document, and semantic overrides/code-linked refresh presentation remain later phases. Data Viewer sorting and filtering apply only to the loaded page and use string ordering. Workspace sizes persist for the app session but are not saved in user preferences. SVG text may be converted to vector outlines by R's SVG device/importer, so plot labels can be editable vector paths rather than native text objects; panel labels are native editable text children.

## Smart Resize / Plot Reflow (2026-10-27)

1. Linked plot panels persist physical plot dimensions in millimeters and a `reflow` or `scale` mode in their document group name. Older `RVS_PANEL|label|variable` markers still load with the previous 177.8 x 127 mm default and Reflow mode.
2. Reflow sends the linked variable name and dimensions to the existing persistent R session. R retrieves the ggplot object from `.GlobalEnv`, renders it using `svglite` when installed or `grDevices::svg` otherwise, and writes to a per-session temporary SVG path. Rust bounds dimensions to 1–1000 mm and SVG size to 16 MiB; the temporary file is removed after success or failure.
3. The generated SVG is imported using `clipboard.importSvg`, grouped as native document vectors, then `object.resizeRPanel` replaces the generated plot subgroup inside one undoable edit while retaining the panel and label identities. R source is never sent to the artboard. Scale mode transforms existing vectors and does not invoke R.
4. The R Plot Properties section accepts width and height in millimeters, an aspect-ratio lock, Reflow/Scale mode, and Apply Resize. A manual transform of a selected panel is observed and synchronized on pointer release, avoiding repeated R renders during a drag. Successful renders update the persisted dimensions; a render/import/engine failure leaves the previous vector subgroup intact for explicit property changes.
5. Windows R 4.6.0 + ggplot2 integration verifies 100 x 80, 160 x 80, and 100 x 120 mm device outputs, vector SVG geometry, named ggplot discovery, and a real imported plot reflowed to 100 x 80 mm. Engine tests verify exact physical bounds, panel metadata and ID preservation, vector scaling, and single-step undo. A separate Windows `cargo run -p vectorcraft -- --control 7979` launch and native screenshot verified that the Studio and existing editor render together; the Properties section was visible in its collapsed state. The resize controls themselves were not exercised with pointer input in that GUI session.

Remaining limitation: `grDevices::svg` rounds its intrinsic SVG dimensions to whole points, so SVG device geometry can differ by a fraction of a millimeter from the requested physical dimensions. The native document subgroup is fitted to the exact requested size after import. Text emitted by the base R SVG device may be outlined paths rather than native text; this preserves vector appearance and editability of shapes but not text semantics.

## Phase 3.5 R editor completion and highlighting (2026-10-27)

- The R script `TextEdit` keeps its existing widget ID and undo/redo state, with a cached lexical R highlighter for keywords, constants, numbers, escaped and raw strings, comments, function calls, assignment/operators, namespaces, identifiers and punctuation. Colors use the active VectorCraft theme palette; incomplete strings and unfinished expressions are handled as editor text.
- egui's completion popup supplies Up/Down navigation, Tab/Enter acceptance and Escape dismissal. Ctrl+Space opens broad suggestions; ordinary typing filters without opening an empty-prefix popup. Function suggestions include available signatures and insert `()` with the cursor inside. Shift+Tab outdents selected lines; Tab retains the code editor's indentation insertion.
- Suggestions combine R keywords and constants, base functions, loaded namespace exports, script and persistent-environment bindings, and data-frame columns after `$` or `[[`. Metadata refresh runs asynchronously against the existing R session; it inspects names and signatures without evaluating typed expressions or serializing frame contents. Accepting a suggestion closes the popup until the script changes or Ctrl+Space is pressed.
- Completion metadata is collected asynchronously from the existing persistent R session and refreshed after R execution. The bounded `COMPLETE` query reads base and already loaded namespace exports, `.GlobalEnv` names, signatures, and names-only metadata for data frames (up to 4,000 objects, 500 columns per frame and 12,000 total columns). Active bindings are skipped; data-frame values are not serialized. No new R process is started per keystroke.
- Windows verification: real R 4.6.0 metadata test confirms base and user functions, object names, data-frame columns including a non-syntactic name, and `stats` exports. Tokenizer, static provider, Shift+Tab, editor-frame and existing R completion tests passed. Clippy, `cargo fmt --all --check`, `cargo check -p vectorcraft --offline`, and `git diff --check` passed. GUI screenshots verified syntax-styled R code, live `plot_A`/ggplot2 suggestions with signatures, and Tab acceptance without an extra tab character; the final acceptance screenshot confirms the popup closes.
- Remaining editor work: line-number gutter, current-line and matching-bracket highlights, auto-pair insertion, Enter auto-indentation, and indenting a multi-line selection with Tab are not implemented. Package namespace suggestions use already loaded namespaces only; un-loaded packages are not loaded just to inspect their exports.

## Phase 3.5 Multi-Tab R script editor (2026-10-27)

- The source editor now keeps a stable-ID document per open R file. Each has its own text, path, saved snapshot, completion/highlight state and pending cursor; egui editor and scroll IDs are derived from the document ID so cursor, selection, scroll and undo state stay with the tab. The source tab strip is independently horizontally scrollable above the editor; its active and dirty states use the existing VectorCraft theme. The seven bottom utility tabs remain independent.
- New, Open, Save, Save As and Close actions are available in the toolbar and Ctrl+N/O/S/Shift+S/W shortcuts. Ctrl+Tab and Ctrl+Shift+Tab cycle source tabs. Opening the same normalized path activates its existing tab. Closing a dirty tab presents Save/Discard/Cancel; the last tab close creates a fresh untitled script. File dialogs use existing picks/services, and a regular Save compares disk bytes with the snapshot from opening/saving before writing; an external change is reported and protected from overwrite.
- Run and Ctrl+Enter execute the active selection or current expression; Source and Ctrl+Shift+Enter execute only the active script. Current-expression results are associated with their source document ID, and every tab continues using the one shared R session, Console, Environment, Plot Registry, History and package state.
- Windows verification: launched the real `vectorcraft` app with R 4.6.0; confirmed two independent source tabs, active-tab switching and focus transfer, syntax-colored buffers, the dirty-close Save/Discard/Cancel dialog, and the unchanged VectorCraft canvas/theme. In the live R session, sourced `shared_value <- 41` from one tab and `shared_result <- shared_value + 1` from the other; the Environment showed both values (`41` and `42`), confirming shared state across tabs. The shortcut regression test verifies Ctrl+N creates an R tab without creating a VectorCraft document. Focused multi-document, duplicate-path, save-conflict, close-flow and shared-session tests pass. Build, clippy, format and diff checks pass; the full workspace CI suite was not rerun for this change.
- Session restoration of open script paths and order is not wired because the current UI preference persistence does not store R workspace documents. Save failures and external modification conflicts leave the tab open and its dirty state intact; use Save As to preserve both versions.
